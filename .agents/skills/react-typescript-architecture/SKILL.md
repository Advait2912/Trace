# React + TypeScript Architecture

## Core Philosophy
The web layer is an interactive, observational window into the computational model. 
**The web UI must NEVER independently reimplement the mathematical or algorithmic model.** 
The Python computational core running via Pyodide is the single source of truth.

## Principles & Rules
1. **Model Contract & Typed Boundary:**
   - Define strict TypeScript interfaces and schemas that mirror the Python core's fixture schemas.
   - All state ingested from Pyodide (parameters, trajectories, matrices, diagnostics) must be strongly typed with zero `any` types.

2. **Pyodide Worker Bridge:**
   - Long-running or iterative simulations must run in a Web Worker via Pyodide to keep the main UI thread at a responsive 60fps.
   - Design a clean, message-passing bridge (`RunSimulationMessage`, `SimulationStepMessage`, `SimulationErrorMessage`).
   - Implement clear loading, initializing, running, and error states for the WASM runtime.

3. **Decoupled State Management:**
   - Keep simulation state (data generated by the model) strictly separated from UI view state (selected tab, active probe, viewport zoom, playback speed).
   - Use unidirectional data flow: UI actions dispatch parameter changes $\to$ Pyodide executes computation $\to$ Typed state updates UI.

4. **Zero Bloat & Framework Discipline:**
   - Avoid generic, bloated UI component libraries (e.g., massive design systems built for SaaS dashboards).
   - Use clean, modular React primitives, modern hooks, and Vanilla CSS/CSS Modules for layout and styling.
   - Ensure fast initial load times and minimal bundle overhead.
